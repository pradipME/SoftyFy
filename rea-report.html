2. Player State & Reducer

2.1 State Shape

  • queue, currentIndex, currentSong, status ('loading' | 'playing' | 'paused' | 'error'), positionSec, durationSec, volume, muted, shuffle, repeatMode ('off' | 'all' | 'one'), streamingQuality ('auto' | 'high' | 'low'), activeQuality ('hq' | 'lq' | null), selectionEpoch, playIntent.
  • playIntent is a one-shot token ({ id, kind: 'play' | 'pause' }); the provider effect picks it up, acts, then dispatches CLEAR_PLAY_INTENT.

2.2 Key Actions

  • PLAY_SONG({ song, queue, index }) — sets queue + bumps selectionEpoch + sets playIntent(play)
  • AUTO_NEXT / NEXT / PREV — advance via buildOrder (shuffle-aware)
  • SET_STREAMING_QUALITY — session preference only; applied at next song load, never reloads current
  • SET_VOLUME — sets volume; unmutes when volume > 0
  • RESTART — seeks to 0 on repeat: 'one'

3. Audio-Playback Pipeline

3.1 Source Resolution

buildAudioCandidates() returns exactly one candidate (GitHub Release URL). Google Drive fallback was removed because 403 responses with key-flagging and Sec-Fetch-Site: cross-site made it unreliable. Failure now triggers retry-with-backoff (1 s → 4 s), not a second host.

3.2 Quality Decision

Per song: pickAudioSource() chooses HQ or LQ using streamingQuality preference + networkMemory (time-to-buffer and stall counts). The Network Information API is NOT consulted directly; when its fields are absent, the connection is assumed fast.

4. UI Interactions

  • SongRow click — if current song → togglePlay(); else playSong(song, queue)
  • Keyboard shortcuts (global keydown): Space = play/pause, ← / → = seek ±5 s, M = mute toggle; ignored when focus is in an input
  • PlayerBar — mini-player; maps status → loading spinner / play / pause / error icon; falls back to durationSec for display
  • NowPlayingSheet — auto-opens when selectionEpoch > 0 (user-initiated play only, not auto-advance)
  • QualitySetting — radiogroup (Auto / High / Low); preference persists in localStorage under softyfy:preferences
  • QualityNote — distinguishes manual low quality vs automatic low quality via isManualQualityReason()
  • useBackInterception — pushes a history.pushState({ softyfyOverlay: true }) marker so Back closes overlays without disturbing HashRouter routing
  • MediaSession — position state updated; metadata set on song change

5. Diagnostics (mediaDebug.ts)

  • Inert unless ?debug URL param or localStorage['softyfy-debug'] === '1'
  • Ring buffers (max 400 entries each): events, stalls, recovery attempts
  • Logs go to in-memory arrays only — never console

6. Potential Bugs & Edge Cases

B1 — Stale playIntent re-run race (PlayerContext.tsx ~line 448)
The song-load effect reads playIntent from state. Under React StrictMode (double-effect in dev) or rapid queue changes, a cleared-then-restored intent could re-trigger a load for the wrong index. Mitigated by the one-shot CLEAR_PLAY_INTENT dispatch, but timing windows exist.
B2 — SET_VOLUME auto-unmute (playerReducer.ts)
SET_VOLUME unmutes whenever volume > 0 (muted: volume === 0 ? state.muted : false). Adjusting the volume slider while deliberately muted will unexpectedly unmute.
B3 — AUTO_NEXT forces status 'loading' even when paused (playerReducer.ts)
After an auto-next the status is set to 'loading' and the playIntent is set to play, meaning auto-advance always starts playback even if the user had explicitly paused before the track ended.
B4 — Stall watchdog false positives on silence (useAudioPlayer.ts)
If a track has a silent intro, currentTime may not change for several seconds and the watchdog (10 s) could falsely declare a stall and trigger a recovery reload.
B5 — isSlowConnection assumes "fast" when Network API absent (networkMemory.ts)
No navigator.connection → falls back to fast-connection defaults. On slow networks without the API (Firefox, older Safari) the quality downgrade is never triggered.
B6 — useBackInterception marker leak (useBackInterception.ts)
If the user navigates away abruptly (external link, tab close) while an overlay is open, the softyfyOverlay history marker is never popped; the next Back press may close nothing.
B7 — loadAndPlay shouldPlay=false path (useAudioPlayer.ts)
When shouldPlay is false the hook loads the new source but does not explicitly pause() the element; if the previous song was playing, the audio element may briefly keep playing the old source until the new src takes effect.
B8 — bufferedMeasurableAhead returning null treated as healthy (useAudioPlayer.ts)
When buffered is empty (null ahead), the buffer guard treats it as "not starved" rather than "unknown", so playback can enter a starvation loop without triggering recovery.
B9 — No UI feedback for forced HQ (PlayerContext.tsx / audioSources.ts)
When streamingQuality === 'auto' and memory says LQ, activeQuality is set to 'lq', but the PlayerBar quality badge may not visibly change (depends on display logic), leaving users unaware of a quality downgrade.
B10 — AbortError vs autoplay-policy conflation (useAudioPlayer.ts)
When play() rejects with an autoplay-policy error (user hasn't interacted yet), it is caught as a generic error and status is set to 'error', not distinguished from a network abort. This may show a misleading "playback error" on first visit.
B11 — Stale resumePositions entries never cleaned (storage.ts / PlayerContext.tsx)
Positions are saved per song but never evicted when a song is removed from the library or the queue; the resume map grows unbounded over a long session.
B12 — onStalled + onWaiting both set loading (useAudioPlayer.ts)
Both events fire on network stall, causing two rapid status updates to 'loading'; UI may flicker between loading states.
B13 — restart threshold RESTART_THRESHOLD_SECONDS = 3 (PlayerContext.tsx)
Magic constant: if user is within 3 s of start, PREV restarts rather than going to the previous track; not configurable, not documented in UI.
B14 — warmNextSong race on rapid song changes (PlayerContext.tsx ~line 232)
The warm-target guard checks warmTargetRef after a throttle; if the user rapidly changes songs, the throttle window may block the new target and the previously warmed song stays wasted.
B15 — Cover palette fallback silent (useSongPalette.ts)
When cover image load fails for palette extraction, the hook silently falls back to default colors; no warning logged, so theming bugs are hard to diagnose.

7. Data-Flow Summary

User click (SongRow / AlbumCard)
  → dispatch(PLAY_SONG)  [reducer: queue, selectionEpoch++, playIntent]
    → PlayerContext effect detects playIntent
      → pickAudioSource(streamingQuality, networkMemory, song)
        → buildAudioCandidates(song, tier)  [single GitHub URL]
        → audioRef.load() via loadAndPlay() in useAudioPlayer
        → MediaSession metadata + position state
      → dispatch(CLEAR_PLAY_INTENT)
    → AppShell sees selectionEpoch > 0 → opens NowPlayingSheet

Audio element events (timeupdate / ended / stalled / error / waiting)
  → useAudioPlayer handlers
    → dispatches: SET_POSITION, AUTO_NEXT, SET_STATUS, RECOVER_ATTEMPT
      → reducer updates state → consumers re-render

Warm preload (throttled 3 s)
  → fetch HEAD / range probe on next queue item's URL
    → caches Audio element via audioCache
